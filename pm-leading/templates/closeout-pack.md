# 收尾阶段模板包（Closeout Pack）

> 项目验收和收尾时用。包含：验收清单、项目复盘（经验教训）。
> 关键提醒：**验收清单要在项目"开始"时就和甲方定好**，收尾时只是拿出来对照打钩，而不是到这时才现编——现编必生纠纷。

---

## 模板 1：验收清单（Acceptance Checklist）

```
# 验收清单：<项目名称>

## 交付物验收（对照范围说明书逐条核对）
| # | 交付物 | 验收标准（怎么算通过） | 结果 | 备注 |
|---|--------|------------------------|------|------|
| 1 | | | ✅/❌ | |
| 2 | | | | |

## 质量验收
| 项 | 标准 | 结果 |
|----|------|------|
| 功能完整性 | 覆盖约定的全部功能 | |
| 性能 | <如：并发/响应时间达标> | |
| 稳定性 | <如：无 P0/P1 缺陷> | |
| 文档 | 技术文档 + 用户手册齐全 | |

## 未满足项处理
| 未满足项 | 属于（范围内欠缺/范围外新增） | 处理方案 | 时间 |
|----------|-------------------------------|----------|------|
| | | | |

## 验收确认
- 甲方验收人签字：__________  日期：______
- 验收结论：[通过 / 有条件通过 / 不通过]
```

**每条验收标准都要能判断"通过与否"**。写不出判据的（如"体验好"），要么细化成可测的（如"关键操作 3 步内完成"），要么和甲方当面确认到能打钩为止。

---

## 模板 2：项目复盘（经验教训 / Retrospective）

项目结束别急着散，花 1 小时复盘，把教训变成下次的能力。**复盘找系统原因，不追责个人（Blameless）。**

```
# 项目复盘：<项目名称>

## 结果回顾
- 目标达成情况：<对照项目章程的目标>
- 进度：计划 X，实际 Y，偏差原因
- 成本/工作量：预算 X，实际 Y，偏差原因
- 质量：缺陷情况、返工情况

## 做得好的（继续保持）
- 
- 

## 做得不好的（下次改进）
- 
- 

## 意外与教训
- 发生了什么没预料到的？根因是什么？

## 行动项（把教训落成下次的动作）
| 改进项 | 具体行动 | 负责人 |
|--------|----------|--------|
| | | |

## 沉淀
- 可复用的模板/流程/经验：<记下来，甚至可以更新到本 skill>
- 后续/二期机会：<识别到的新项目线索>
```

**给 AI 的提示**：引导用户复盘时，多问"为什么会这样"而不是"谁的错"；帮他把模糊的感受（"这次沟通不太好"）追问成具体可改进的动作（"下次每周固定同步一次接口变更"）。
