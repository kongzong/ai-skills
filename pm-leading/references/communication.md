# 沟通管理

> 📖 **这是后台深层参考**——新手日常用前台的[案例](case-study.md)/[playbook](playbook.md)/[模板](../templates/)即可，遇到下面情况再翻到这里。
> **何时翻到这里**：想设计一套完整的沟通机制与干系人管理体系，或在 playbook #2（老板催进度）/#7（跨部门推不动）/#17（业务方不回消息）之后想把沟通从"临时应付"变成"固定机制"。
> **它比 playbook/案例多讲**：干系人识别与影响力/态度分析（权力-利益矩阵）、沟通计划的系统编制（跟谁、说什么、什么形式、多久一次）；playbook 给具体话术，这里给沟通的顶层设计。

## 定义

决定何时、向谁、有效地传达哪些信息，使所有项目参与人员理解其含义的过程；记载项目相关信息并适时生成、收集、分发、保存与安排的活动。

## 一、启动阶段：建立沟通

### 01 与客户建立伙伴关系
- **操作方式**：向客户展示我们团队可满足其需求的能力（业务、技术专业性等信息），提供方法论相关培训与说明会；若使用不熟悉的技术，可演示我们团队过往类似成功案例；迅速把握客户的业务环境、业务本质与技术变化；确认客户是否了解所用方法论，是否自有方法论与标准步骤。
- **目标**：让客户信任我们团队的能力，提升双方成功机会。

### 02 制定初期沟通计划
- **操作方式**：定义所有沟通相关活动并正式文档化（启动与计划阶段的沟通计划）；确认所有相关组织与客户均在计划中定义；确认对外沟通全部定义；更新制约条件与议题。
- **交付物**：沟通计划书、沟通指导

### 03 有关角色与责任的沟通
- 对全体项目组与初期角色/责任进行沟通，使成员接受各自责任并达成协议；对角色与责任定义书进行协调并更新。

### 04 实施 Kick-off 会议
- **操作方式**：项目启动时正式沟通；会前准备资料、确定参会人/地点/时间、安排议程；讨论各自目标、角色、责任；实施会议并更新项目文件、制作并发布会议纪要；将讨论中的假设、决定事项、确认的制约条件文档化。
- **理由**：使成员认识项目目标与各人角色/责任，理解项目方向。

### 05 项目公告
- **操作方式**：评价公告必要性，选定适当媒体（文档、邮件等），制定并审批公告内容（必要时取得客户审批）；按对象准备不同详略的内容。
- **目标**：使受项目直接/间接影响的个人与组织认识其会受到的影响。

## 二、计划阶段：更新沟通计划

### 01 评审需求与报告细化
- 将所有正式评审会议及报告事项更新进沟通计划；修改报告模板；确认沟通对象、事项、时间、方法并文档化；正式化评审与报告的理解确认过程。

### 02 其他沟通需求细化
- 将项目所需的其他沟通活动（如客户经营层会议、项目结束评审等）更新进沟通计划；确认听众后确认信息，与相关组织沟通，依反馈修改。

### 03 持续改善与客户关系
- 通过与客户接触获取实施工作的反馈（如客户满意调查表），评价反馈并反映到项目计划活动中；持续构筑强有力的业务关系。

## 三、实施 / 控制阶段：进度信息传达

### 01 发行进度现况报告书
- 按项目进度与沟通计划定义的周期，收集项目进展信息，制定并分发进度现况报告书。

### 02 项目团队进度例会及事后措施
- 召开团队进度例会，跟踪议题与措施项。

### 03 管理层进度报告会及事后措施
- 向管理层报告进度，落实事后措施。

### 04 履行沟通计划内其他活动
- 按计划执行其余沟通活动。

### 05 沟通计划监控及事后措施
- 监控沟通计划执行，采取改进措施。

### 06 持续客户关系改善
- 持续收集反馈、改善关系。

## 四、结束阶段：沟通计划结束

- 确认沟通计划全部履行完毕；完成最终项目报告与关系移交。

## 阶段活动汇总

```
启动：建立沟通（伙伴关系 / 初期计划 / 角色责任沟通 / Kick-off / 项目公告）
计划：更新沟通计划（评审需求细化 / 其他需求细化 / 持续改善关系）
实施控制：进度信息传达（进度报告 / 团队例会 / 管理层报告 / 其他活动 / 监控 / 关系改善）
结束：沟通计划结束
```
