# 风险管理

> 📖 **这是后台深层参考**——新手日常用前台的[案例](case-study.md)/[playbook](playbook.md)/[模板](../templates/)即可，遇到下面情况再翻到这里。
> **何时翻到这里**：想系统地识别、评估并持续跟踪风险，或在 playbook #5（依赖拖延）/#9（风险爆了）/#15（关键人离职）之后想建立常态化的风险管理机制。
> **它比 playbook/案例多讲**：风险管理全流程（识别→定性/定量分析→应对策略→监控），风险值=可能性×影响的打分法，以及规避/转移/减轻/接受四类应对策略的选用；playbook 给单个风险的救火，这里给整套防火机制。

## 定义

系统地识别项目风险因素，进行评价与管理；为有效达成项目目标，系统找出风险、评价并采取应对措施。

## 一、启动阶段：识别风险

### 01 实施初步风险评价
- **操作方式**：制作环境特征模板（技术环境、工具、人员技术、制约、复杂度），运用评价模板评价总体风险；对评价属性高的风险进一步细化；更新议题/决议与假设/制约清单。
- **交付物**：总体风险评价

### 02 订立初期风险管理计划
- **操作方式**：制定风险管理计划文件，含项目上的责任与作用、工具、风险管理步骤。
- **须包含**：团队成员各自的作用与责任；有规律的风险管理活动日程；风险交付物的初期识别与定量化方案；识别/预防/减轻风险的工具；风险分析与排优先级的方法；控制与追踪风险减轻活动的方法；应急计划/应急储备的管理方法。
- **交付物**：风险管理计划书

### 03 启动详细识别风险
- **操作方式**：依据初步风险评价结果与优先级、类似项目的历史经验、经验丰富的专家，详细识别并文档化具体风险；把合同中未解决的议题文档化；参考提案、提案书识别所有风险、假设、议题、制约。
- **要点**：将更新的议题/决定事项与假设/制约清单与项目组共享很重要。

## 二、计划阶段：制定风险应对方案

### 01 初步风险评价细化
- 检查并更新启动阶段制定的初步风险评价与初期风险管理计划；制作/修订标准项目属性（规模、工作量、成本、结构、技术、项目影响等）与总体风险评价模板。

### 02 识别风险、文档化与分类
- 根据提案、假设、制约、议题、风险项，以及客户与合作企业合同中的突出议题、类似项目过往经验识别潜在风险；需详细调查时运用检查表（Check List）；分析 WBS 不确定部分与进度中未知信息；对识别到的风险分类（内部可监控 / 外部难监控）。

### 03 评价风险并确定优先级
- 将风险发生可能性与发生后的影响程度组合，计算风险值（可能性 × 影响），确定优先级；识别最深刻的风险，更新风险清单与议题/假设清单。

### 04 评价风险并制定处理计划
- 对优先风险制定处理计划（接受、规避、减轻、转移、应急计划）；文档化风险管理大纲（谁/什么/何时/何地/为何/怎样识别）；应急计划须准备日程、缓冲、人员、附加设备等；将评价/管理责任分配给团队成员，使其作为各风险的负责人。

### 05 将风险计划用于其他计划要素
- 为执行风险处理计划，在成本、进度、资源方面反映影响；考虑是否将风险管理费用纳入预算；确认风险措施与应急计划有确定的时间与资源；对高风险项协商延期交货。

## 三、实施阶段：实施应对方案

- 按计划执行风险应对措施，持续监控风险状态，更新风险登记册。

## 四、控制阶段：风险监控与应对变更

- 跟踪风险登记册，监控风险触发与变化；当风险发生或评价变化时，启动应对方案变更（经变更管理步骤）。

## 五、结束阶段：结束风险管理

- 确认所有风险已关闭或移交；将风险管理经验教训纳入项目复盘。

## 风险应对策略速查

| 策略 | 含义 |
|------|------|
| 接受 | 不主动处理，接受其影响 |
| 规避 | 改变计划以消除风险源 |
| 减轻 | 降低发生可能性或影响 |
| 转移 | 通过合同/保险将影响转嫁第三方 |
| 应急计划 | 预设触发条件与应对预案 |

## 阶段活动汇总

```
启动：识别风险（初步评价 / 初期计划 / 详细识别）
计划：制定应对方案（评价细化 / 文档化分类 / 优先级 / 处理计划 / 融入其他计划）
实施：实施应对方案
控制：监控与应对变更
结束：结束风险管理
```
