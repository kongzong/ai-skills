# 执行阶段模板包（Run Pack）

> 项目推进中用。包含：风险登记册、沟通计划、状态周报、变更请求。
> 给 AI 助手：帮用户填初稿，别只给空表。

---

## 模板 1：风险登记册（Risk Register）

新手从 Top 5 风险开始就够，不求大全，求"最要命的盯住"。

| # | 风险描述 | 可能性(高/中/低) | 影响(高/中/低) | 优先级 | 应对策略 | 具体应对措施 | 负责人 | 状态 |
|---|----------|------------------|----------------|--------|----------|--------------|--------|------|
| 1 | | | | | | | | 跟踪中 |
| 2 | | | | | | | | |

- **优先级** = 可能性 × 影响（高×高 = 最高，先管）。
- **应对策略**五选一：接受 / 规避 / 减轻 / 转移 / 应急计划。
- **每周扫一遍**：状态有没有变、有没有新风险、有没有可以关闭的。

**新手示例**：
| 风险描述 | 可能性 | 影响 | 应对措施 | 负责人 |
|----------|--------|------|----------|--------|
| 甲方数据延迟提供，阻塞开发 | 中 | 高 | 先用 mock 数据并行开发；每周跟甲方确认进度；书面锁定交付日 | 我 |
| 核心开发只有 1 人，病假即停摆 | 中 | 高 | 关键模块做知识共享+文档；预留 backup 人选 | 我 |

## 模板 2：沟通计划

```
# 沟通计划：<项目名称>

## 对上汇报（老板 / 甲方）
- 形式：<周报 / 周会>
- 频率：<每周五 / 每周一次>
- 内容：进度、风险、需要的决策支持

## 对内同步（团队）
- 每日站会：<时间>，15 分钟
- 任务看板：<工具/位置>
- 问题上报：<渠道>

## 里程碑演示
- 每个里程碑向甲方演示确认一次

## 干系人清单
| 干系人 | 关注什么 | 沟通方式 | 频率 |
|--------|----------|----------|------|
| | | | |
```

## 模板 3：状态周报

```
# 项目周报：<项目名称>  <日期>

## 一句话结论
整体进度：[正常 / 有风险 / 已延期]  <一句原因>

## 本周完成
- <基于事实：完成了里程碑X / N 个任务>

## 进行中
- <任务>（预计 <日期> 完成）

## 下周计划
- <任务>

## 风险与问题 ★别省
| 风险/问题 | 影响 | 应对 | 需要谁支持 |
|-----------|------|------|-----------|
| | | | |

## 需要您决策 / 协调
- <明确告诉老板需要他做什么>
```

**核心原则**：报忧比报喜重要。周报最大价值是**提前暴露风险、争取支持**，不是展示你多忙。

## 模板 4：变更请求（Change Request）

任何范围/需求/进度的改动都走这个。**没走这个流程的改动 = 范围失控的开始。**

```
# 变更请求 CR-<编号>

## 变更内容
<要改什么，具体描述>

## 变更原因
<为什么要改>

## 影响评估 ★关键
- 对范围的影响：<新增/修改了什么>
- 对进度的影响：<+N 天 / 里程碑推迟到…>
- 对成本/人力的影响：<+X 人日>
- 对其他任务的影响：<有无连锁>

## 建议方案
[ ] 接受，相应调整计划（新交付日：____）
[ ] 接受，但砍掉 <某功能> 以保工期
[ ] 拒绝 / 转二期

## 审批
- 申请人：______  日期：______
- 审批人（甲方/老板）：______  决定：______  日期：______

## 批准后动作
- [ ] 更新范围说明书
- [ ] 更新 WBS / 时间表（基线）
- [ ] 同步团队
```

**给 AI 的提示**：用户描述"要加个功能"时，主动帮他填这张单，尤其把**影响评估**算出来给决策者看——这是把"范围蔓延"变成"有意识的决策"的关键动作。
